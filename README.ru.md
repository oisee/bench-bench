# Bench Bench
English · [Русский](README.ru.md) · [Українська](README.uk.md) · [Deutsch](README.de.md)

Воспроизводимый бенчмарк агентов для программирования: сравнивается сочетание модели, оболочки
(Claude Code, Codex или Pi) и уровня усилий. Агент работает в песочнице, а результат проверяют
скрытые тесты. Можно подключить свою модель; система SAP не нужна.

## Быстрый запуск

Нужны Linux (подойдёт WSL2), Docker, доступ к модели и отдельно распространяемый пакет заданий ABAP
(его можно запросить у сопровождающих). В `PACKAGE_ROOT` укажите корень полного пакета с каталогом `repo/`;
каталог результатов должен быть доступен для записи UID 1000. На хосте должны работать пространства имён bubblewrap.
После клонирования репозитория выполните из его корня:

```bash
docker build -f docker/Dockerfile -t abap-bench .
export PACKAGE_ROOT=/path/to/abap-package
export API_KEY  # заранее задайте значение в оболочке или менеджере секретов
mkdir -p output
docker run --rm --security-opt seccomp=unconfined -p 8080:8080 \
  -v "$PACKAGE_ROOT:/pkg:ro" -v "$PWD/output:/out" -e API_KEY \
  abap-bench --agent claude --model demo-model --api-base https://example.org \
  --api-key-env API_KEY --tier ember --env 3 --no-internet --port 8080
```

Замените модель и адрес на свои. Для Claude нужен API, совместимый с Anthropic; для `--agent codex` —
Responses API (обычно адрес с `/v1`), для `--agent pi` — Chat Completions API.
`--port` открывает страницу прогресса на `http://localhost:8080`.
[Подробности запуска](README.md#one-command-native-abap-runs).

## Задания и инструменты

Результаты разных наборов публикуются отдельно:

- **PR-6:** 6 заданий из реальных принятых pull request, уровни L1–L3. Агент получает репозиторий на
  родительском коммите PR и краткое описание, затем реализует изменение за отведённое время.
  Оценка — по скрытым тестам самого PR. Описания в `tasks/`: `L1a-osg678`, `L1b-osg680`, `L2a-osg693`,
  `L2b-abapiti87`, `L3a-minz39`, `L3b-abapiti95`. [Список заданий](README.md#the-tasks).
- **Нативный ABAP:** отдельный пакет из 337 заданий из abapGit, open-abap-core, open-abap-apc,
  open-steamgate (osg), osg-demo, pia, zllm, zork-abap, zvdb и zmjs. Группы исходников: старый публичный
  код (190), свежий код (109), собственные публичные репозитории сопровождающего (38).
  **L0 infill** — восстановить строку, блок или тело конструкции внутри метода; **L1** — реализовать
  метод целиком. Для оценки берут только тело целевого метода, вставляют его в исходные файлы и
  запускают скрытые тесты. Отдельная проверка на неверных ответах подтверждает, что оценщик их отклоняет.
  Наборы по размеру: **ember / SMOKE-4 (4)**, **SMOKE (12)**, **MEDIUM (69 в v2.2–v2.3; 54 с v2.4)**,
  **FULL (337)**. У заданий есть версии (`id@n`), а в каждом запуске сохраняется версия окружения
  (v2.3 = env 3). В репозитории находятся [адаптер](bin/abap-tasks.sh) и
  [инструкция](tasks-abap/README.md), сам пакет распространяется отдельно.
- **Дополнительные наборы ABAP, отдельные таблицы:** agentic — 10 заданий из реальных принятых изменений,
  уровни L1–L3, лимиты 30–60 минут; synthetic — 15 заданий с внесёнными ошибками или удалёнными возможностями.
  Их проверяют тестами изменения, тестами на основе эталонного решения и 200 дифференциальными сценариями
  на задание, с фиксированным seed.

В песочнице на PATH доступен **`osg-abap`**:

| Команда | Что проверяет |
|---|---|
| `osg-abap lint` | Быстрая диагностика исходников |
| `osg-abap check` | Синтаксис и активация |
| `osg-abap test` | Модульные тесты рабочего каталога, включая написанные агентом в `<class>.clas.testclasses.abap` |

Скрытые тесты агенту недоступны. Файлы `AGENTS.md` / `CLAUDE.md` в рабочем каталоге объясняют команды,
а с v2.3 рекомендуют писать собственные тесты. Инструмент работает офлайн; скрипты сборки исходного
репозитория не нужны.

Для ABAP веб-инструменты оболочек отключены. Сетевой доступ разрешён только к модели и
`help.sap.com`, `rules.abaplint.org`, `abaplint.app`; с `--no-internet` — только к модели.
Ключи своего endpoint, z.ai, Alibaba, Anthropic API и Azure остаются вне песочницы;
учётные данные Claude OAuth и ChatGPT по-прежнему попадают внутрь.

Все остальные сведения — методика, результаты, настройка PR-6 и безопасность — в [английском README](README.md).
