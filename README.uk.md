# Bench Bench
English · [Русский](README.ru.md) · [Українська](README.uk.md) · [Deutsch](README.de.md)

Відтворюваний бенчмарк агентів для програмування: оцінюється поєднання моделі, оболонки
(Claude Code, Codex або Pi) та рівня зусиль. Агент працює в пісочниці, а результат перевіряють
приховані тести. Можна підключити власну модель; система SAP не потрібна.

## Швидкий запуск

Потрібні Linux (підійде WSL2), Docker, доступ до моделі та окремо розповсюджуваний пакет завдань ABAP
(його можна запросити в супровідників). У `PACKAGE_ROOT` вкажіть корінь повного пакета з каталогом `repo/`;
каталог результатів має бути доступний для запису UID 1000. Хост має підтримувати простори імен bubblewrap.
Після клонування репозиторію виконайте з його кореня:

```bash
docker build -f docker/Dockerfile -t abap-bench .
export PACKAGE_ROOT=/path/to/abap-package
export API_KEY  # заздалегідь задайте значення в оболонці або менеджері секретів
mkdir -p output
docker run --rm --security-opt seccomp=unconfined -p 8080:8080 \
  -v "$PACKAGE_ROOT:/pkg:ro" -v "$PWD/output:/out" -e API_KEY \
  abap-bench --agent claude --model demo-model --api-base https://example.org \
  --api-key-env API_KEY --tier ember --env 3 --no-internet --port 8080
```

Замініть модель і адресу на власні. Для Claude потрібен API, сумісний з Anthropic; для `--agent codex` —
Responses API (зазвичай адреса з `/v1`), для `--agent pi` — Chat Completions API.
`--port` відкриває сторінку прогресу на `http://localhost:8080`.
[Докладніше про запуск](README.md#one-command-native-abap-runs).

## Завдання та інструменти

Результати різних наборів публікуються окремо:

- **PR-6:** 6 завдань із реальних злитих pull request, рівні L1–L3. Агент отримує репозиторій на
  батьківському коміті PR і стислий опис, після чого реалізує зміну за відведений час.
  Оцінювання — за прихованими тестами самого PR. Описи в `tasks/`: `L1a-osg678`, `L1b-osg680`, `L2a-osg693`,
  `L2b-abapiti87`, `L3a-minz39`, `L3b-abapiti95`. [Перелік завдань](README.md#the-tasks).
- **Нативний ABAP:** окремий пакет із 337 завдань з abapGit, open-abap-core, open-abap-apc,
  open-steamgate (osg), osg-demo, pia, zllm, zork-abap, zvdb та zmjs. Групи вихідного коду: старий публічний
  код (190), свіжий код (109), власні публічні репозиторії супровідника (38).
  **L0 infill** — відновити рядок, блок або тіло конструкції всередині методу; **L1** — реалізувати
  метод повністю. Для оцінювання беруть лише тіло цільового методу, вставляють його в початкові файли й
  запускають приховані тести. Окрема перевірка на хибних відповідях підтверджує, що оцінювач їх відхиляє.
  Набори за розміром: **ember / SMOKE-4 (4)**, **SMOKE (12)**, **MEDIUM (69 у v2.2–v2.3; 54 від v2.4)**,
  **FULL (337)**. Завдання мають версії (`id@n`), а кожен запуск зберігає версію середовища
  (v2.3 = env 3). У репозиторії є [адаптер](bin/abap-tasks.sh) та
  [інструкція](tasks-abap/README.md), сам пакет розповсюджується окремо.
- **Додаткові набори ABAP, окремі таблиці:** agentic — 10 завдань із реальних злитих змін,
  рівні L1–L3, ліміти 30–60 хвилин; synthetic — 15 завдань із внесеними помилками або вилученими можливостями.
  Їх перевіряють тестами зміни, тестами на основі еталонного розв'язку та 200 диференційними сценаріями
  на завдання, із фіксованим seed.

У пісочниці на PATH доступний **`osg-abap`**:

| Команда | Що перевіряє |
|---|---|
| `osg-abap lint` | Швидка діагностика вихідного коду |
| `osg-abap check` | Синтаксис та активація |
| `osg-abap test` | Модульні тести робочого каталогу, включно з написаними агентом у `<class>.clas.testclasses.abap` |

Приховані тести агенту недоступні. Файли `AGENTS.md` / `CLAUDE.md` у робочому каталозі пояснюють команди,
а від v2.3 заохочують писати власні тести. Інструмент працює офлайн; скрипти збирання вихідного
репозиторію не потрібні.

Для ABAP вебінструменти оболонок вимкнено. Мережевий доступ дозволено лише до моделі та
`help.sap.com`, `rules.abaplint.org`, `abaplint.app`; з `--no-internet` — лише до моделі.
Ключі власного endpoint, z.ai, Alibaba, Anthropic API та Azure залишаються поза пісочницею;
облікові дані Claude OAuth і ChatGPT і далі потрапляють усередину.

Решта відомостей — методика, результати, налаштування PR-6 та безпека — в [англійському README](README.md).
